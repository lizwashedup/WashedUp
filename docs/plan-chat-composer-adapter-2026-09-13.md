## Voice: retain the real state machine and gesture target

The microphone is implemented, despite the stale “placeholder” comment at `ChatThread.tsx:1402`. The actual recorder lives at `:1404–1517`; the morph target/overlay at `:2251–2280`.

- `Gesture.Exclusive(pan,tap)` owns the single morph target. Empty-input pan activates after **200 ms**. At release, an upward translation beyond **80 points** locks; otherwise leftward beyond **80 points** cancels; otherwise the held recording stops and sends. The upward branch takes precedence. Tapping with text sends; tapping an empty mic only produces the existing hint haptic. Preserve the thresholds, coordinate frame, gesture order and `runOnJS` callbacks.
- The **150 ms** send/mic crossfade and scale layers remain inside that target. Enlarging its outer bounds is a style change; replacing it with a new nested `Pressable` can change gesture arbitration and is not part of this first pass.
- Modes are `idle`, `holding`, `locked`, and `draft`. Holding renders a pointer-transparent overlay so the original finger gesture continues. Locked exposes trash, pause/resume, stop-to-preview and send. Draft exposes trash, `VoicePlayer` playback and send. `VoiceRecorder.tsx:16–36,90–153` is the presentation contract.
- Android Back cancels an active recording; another handler closes an open inline panel (`ChatThread.tsx:1444–1463`). Preserve both handlers and consumption behavior.
- `useVoiceRecorder.ts:42–72,90–108,129–183` owns expo-audio, microphone permission, high-quality metering, a 48-sample rolling waveform with 80 ms UI emission, duration, pause/resume, stop/cancel and unmount cleanup. `VoicePlayer.tsx:50–129` owns playback, seek and rate. Do not move these hooks, add a recorder remount key or replace the preview player during a style port.
- Audio upload/send remains `uploadAudioToStorage` followed by `sendAudio` (`ChatThread.tsx:1413–1424`). This inventory does not claim new retry persistence or account/room lifetime protection for voice. The topic mutation repair did not change this Plan/Circle/DM pipeline.

## Keyboard and list geometry are existing behavior

Preserve `ChatThread.tsx:872–1013,1346–1347,2029–2036,2085–2115,2291–2306`:

1. Android uses `useAnimatedKeyboard` and an `Animated.View`; iOS uses keyboard-will-show/will-hide events and a normal `View`. Do not restore a `KeyboardAvoidingView` in this screen.
2. Input dock bottom is **max(keyboard height, panel inset)**. The inline panel starts at 280 until an actual keyboard height has been observed, and its Android inset animates over 180 ms. Panel-to-keyboard handoff clears the panel only once the keyboard has taken over.
3. Bottom padding is 8 when keyboard/panel is visible, otherwise `insets.bottom+8`. Preserve Android's extra left/right safe-area padding.
4. Dock height starts at 70 and is measured by the same outer `onLayout`, including reply/edit/mention/countdown content. The inverted list reserves `bottomDockHeight+8` on iOS, and that plus `max(androidKeyboardHeight,panelInset)` on Android. iOS separately shrinks the list with its keyboard/panel margin. Do not count keyboard height twice on iOS.
5. Scroll-to-bottom control uses the same inset plus dock height plus 12. Keep the inverted list's keyboard interaction, visible-content handling and memoized row callbacks. A visual change must not recreate the full message list on each keystroke.

**Platform correction:** the initial unconditional one-line setting was unsafe for native multiline sizing. The [React Native 0.81 TextInput documentation](https://reactnative.dev/docs/0.81/textinput#numberoflines) defines `numberOfLines` as a maximum and notes iOS support under the New Architecture. Installed RN 0.81.5 confirms the mapping to `paragraphAttributes.maximumNumberOfLines` in `node_modules/react-native/ReactCommon/react/renderer/components/textinput/BaseTextInputProps.cpp:160–165`. Installed React Native Web 0.21.0 instead maps the same prop to textarea `rows` in `node_modules/react-native-web/dist/exports/TextInput/index.js:377`. Parent corrected both adapters to apply the one-row setting only on web; the sizing-hook tests alone could not detect a native input line cap.
